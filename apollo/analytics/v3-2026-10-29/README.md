# Статистика проверок Apollo V3

Срез на 29 октября 2026 года · период 10.06–29.10.2026 · даты и месяцы в Europe/Moscow.

Источник: `Ackedze/design-system_stats`, `apollo/stats`, ветка `main`, commit `739e7f52e1206b9b71d8445e65c1408d320af7bd`. Это историческая ревизия исходников анализа. Сырые отчёты V3 удалены из текущей ветки коммитом `67d2bb5dad12207b8f43646b590bd73a4eaa257d`; список удаления точно совпадает с `source-manifest.json`.

## Что показал анализ

- **Уникальных проверок: 1 862**, участников — **47 Figma-пользователей**, календарных дней с активностью — 74. Идентификаторы пользователей присутствуют; должность и принадлежность к команде берутся из самоназваний, отдельно не проверялись.
- **478 974 наблюдения компонентов** в проверках. Это сумма сканирований, включая повторные проверки одних областей.
- **3 639 исходных JSON, 1.32 ГБ (1.23 ГиБ)**. Файлы разных представлений одного запуска объединены по `reportId` / `sourceReportId`.
- **Записей кастомизаций в summaries: 22 063**; подробности доступны для 21 525 записей, содержащих 74 435 изменений свойств.
- По полным отчётам: **66 589 изменений**, из них **17 616** помечены V3 как нарушения, **34 306** не имеют контекстного правила. Всего с доступными агентскими деталями известно 22 927 меток `violation`.
- Основная группа изменений — геометрия и layout: 29 231 наблюдение. Чаще всего по отдельному свойству менялась заливка: 14 625.
- Активность неравномерна: Mariia Netunaeva — 828 запусков, Artem Kiselev — 204; вместе **55,4%**. Пять наиболее активных участников дали 73,0% запусков. Итоги характеризуют эту выборку проверок, а не распространённость ошибок во всех продуктах.

**Мотивов дизайнеров в данных нет.** Под «причинами кастомизации» ниже понимаются изменённые свойства и причины оценки, записанные Apollo. Утверждения «не хватило компонента», «потребовался особый сценарий» или «ошибка дизайнера» из этих JSON вывести нельзя.

## Надёжность статистики и границы сравнения

1. **Дубли представлений исключены.** У 1 319 запусков есть full+agent, у 227 — только full, у 316 — только agent. WIP и predicates связаны с исходным audit. Внутри одного вида нет повторных файлов на один runId; у пар full/agent нет расхождений categoryCounts. Совпадений всех метаданных scan между разными runId не найдено.
2. **543 комплекта неполны** относительно пары full+agent. Причина отсутствия представлений по файлам не установлена; наличие успешного отчёта не доказывает, что все результаты доставки сохранились. 538 записей кастомизаций и 55 980 currentComponents доступны в summaries без соответствующей подробной строки в выбранном представлении.
3. **Нет fileKey у всех 1 862 запусков.** Есть 100 разных имён файлов; это не гарантированно 100 уникальных файлов Figma. Для сочетания «пользователь + имя файла + канал + выбранные nodeId» получилось 484 группы и 1 378 дополнительных повторов. Это прокси областей, а не точная дедупликация макетов. Повторы не объявлены ошибками или дублями доставки.
4. **Выборка смещена в Desktop и нескольких активных участников.** В Desktop 93,3% запусков. Лидеры по одному дню: Artem Kiselev — 197, Mariia Netunaeva — 141, Elena Plevina — 120. Количество запусков не измеряет число уникальных проблем или качество работы человека.
5. **Версии и нормы менялись.** В срезе версии 0.1.0–0.3.0. Динамика violation по месяцам смешивает разные правила, размеры областей, состав участников и частоту повторов. Для будущего Apollo сохранять эту выборку как отдельную историческую базу V3; сравнивать только сопоставимые operation/scope/coverage и определения метрик.
6. **Системные сбои не наблюдаются.** Здесь в основном результаты успешных проверок, а не лог failed/cancelled запусков, сетевых ошибок или падений плагина. По этим данным нельзя посчитать надёжность Apollo или полноту доставки.

## Сохранение аналитики и очистка

29.10.2026 исходные 3 639 JSON-отчётов V3 удалены из текущей ветки коммитом `67d2bb5dad12207b8f43646b590bd73a4eaa257d`. Их суммарный объём — 1 320 771 078 байт (1,23 ГиБ). Список удалённых файлов точно совпал с проверенным аналитическим срезом; новых отчётов в удаление не добавляли. Каталог `apollo/stats` сохранён для следующих версий Apollo.

В этом каталоге сохранены:

- `README.md` и `DETAILS.md` — итоговые выводы, все участники, рейтинги компонентов, свойств и ошибок;
- `summary.json`, `designers.json`, `components.json`, `component-names.json` — сводные метрики и рейтинги;
- `customizations.json`, `error-details.json`, `predicates.json`, `rule-statistics.json` — детализация классификаций, причин и правил;
- `runs.json` — один summary на каждую проверку с пользователем, версией, каналом и scope;
- `source-manifest.json` — пути, размеры, runId и SHA-256 всех исходных JSON;
- `CHECKS.json` — результаты проверок исходного анализа на закреплённой ревизии;
- `CLEANUP.json` — подтверждение состава удаления, контрольные суммы сохранённой аналитики и локального архива.

Из трёх агрегатов убраны массивы примеров `examples`; числа, группировки и классификации сохранены. Подробные примеры остались в локальном архиве.

`analytical-snapshot.zip` (24,03 МиБ) оставлен локально вне репозитория и в Git не добавлен. Он содержит исходный текст анализа, все агрегаты и сжатые наблюдения. `observations.jsonl.gz` сохраняет подробные доступные строки выбранного full/agent: компоненты, слои, изменённые свойства, baseline/actual, bindings и оценки. `auxiliary-observations.jsonl.gz` сохраняет WIP-изменения и predicate evaluations/rules/UI findings отдельно. SHA-256 ZIP закреплён в `CLEANUP.json`.

Это аналитический срез, а не побайтовый backup: в нём нет части contextual snapshots, presentation и развёрнутой assessment evidence. Для точных исходников сохранена Git-ревизия `739e7f52e1206b9b71d8445e65c1408d320af7bd`. История Git не переписывалась: удаление освобождает место в рабочем дереве, старые отчёты остаются в истории.
